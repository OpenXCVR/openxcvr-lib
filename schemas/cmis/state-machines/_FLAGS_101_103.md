# CMIS State Machine Schema Flags for Issues 101-103

- The YAML was authored from the existing enum and page schemas and from CMIS 5.3 sections 6.3.2, 6.3.3, 7.6.7, 8.15.4, and 8.15.5.1.
- CMIS 5.3 Figure 6-3 includes Resetting, Reset, and MgmtInit conceptual MSM states, but the existing `CmisModuleState` enum only contains host-visible encodings for ModuleLowPwr, ModulePwrUp, ModuleReady, ModulePwrDn, and ModuleFault. The MSM YAML is therefore closed to the existing enum and starts at the first host-visible steady state, ModuleLowPwr.
- **RESOLVED:** The MSM `ModuleReady -> ModulePwrDn` transition guard now uses `- forall: { field: page_11h_lane_status.dp_state_host_lane, equals: DPDeactivated }`, correctly asserting the spec's `ModuleDeactivatedT = AND(all DPStateHostLane<N> == DPDeactivated)` (CMIS 5.3 § 6.3.2.2 Table 6-13). `forall` means every instance of the field equals the value. The prior `# APPROXIMATION` comment and single-instance guard have been removed.
- **INTENTIONAL OMISSION (not a defect):** The DPSM `dp_apply_init_pending_from_initialized` and `dp_apply_init_pending_from_activated` transitions, and the NPSM `np_apply_init_pending_from_initialized` transition, are authored for staged control set 0 (SCS0) only. SCS1 produces the same transition shape with a different trigger register; duplicating every SCS0 transition for SCS1 is a mechanical expansion with no new spec semantics. SCS1-equivalent transitions are annotated with `# INTENTIONAL OMISSION` comments in the schema YAML.
- CMIS 5.3 section 7.6.7 says host requests NP initialization or deinitialization by writing to `NPDeinit` bits, but one sentence says `DPDeinit` bits. The NPSM YAML uses the page 16h `np_deinit_lane` field because Table 8-136 and the page schema identify the NP-specific control.
